# 在我们的多线程实现中，当主线程 (即 0 号线程) 退出时，视为整个进程退出，此时需要结束该进程管理的所有线程并回收其资源。
# - 需要回收的资源有哪些？
  * 根据task/mod里的 tid == 0的情况信息
    * 自己的pcb(ProcessControlBlock)
    * 所有子线程的tcb(TaskControlBlock)
    * 占用地址空间
    * 文件描述符表 (fd_table)

# - 其他线程的 TaskControlBlock 可能在哪些位置被引用，分别是否需要回收，为什么？
  * 在pcb的task数组里，需要回收
  * address space也就是memoryset结构体里也有引用，需要提前释放，不然会被重复释放

# 对比以下两种 Mutex 中的实现，二者有什么区别？这些区别可能会导致什么问题？
  * mutex1被提前唤醒，无论是否能pop出等待的锁，
  * mutex2只有不能pop的时候唤醒，pop里如果使用了当前的锁就会死锁
